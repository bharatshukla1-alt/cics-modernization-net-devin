## Summary
- Rows: 25/25 transactions. Analysed: 24. Source missing: 1 (CDV1/COCRDSEC). Unparseable: 0.
- Every program receives its working data through the shared `CARDDEMO-COMMAREA` (COCOM01Y); exceptions: MQ programs (COPAUA0C, COACCT01, CODATE01) start from the MQ trigger message, and COPAUS2C has its own LINK commarea.
- Shared VSAM: ACCTDAT (6 programs), USRSEC (5), CXACAIX (5), CUSTDAT (4), TRANSACT (4), CARDDAT (3), CCXREF (2), CARDAIX (1).
- Db2 tables: CARDDEMO.TRANSACTION_TYPE (COTRTLIC, COTRTUPC only); CARDDEMO.AUTHFRDS (COPAUS2C only).
- IMS: PSBPAUTB (PAUTSUM0/PAUTDTL1) used by COPAUA0C, COPAUS0C, COPAUS1C. TDQs: JOBS (CORPT00C), CSSL (COPAUA0C). No TSQs anywhere.

## Needs Review
- **CDV1 → COCRDSEC**: defined in `Input/csd/CARDDEMO.CSD`, no source in `Input/cbl/`. Supply the source or confirm it is out of scope.
- **COTRN01C** (`Input/cbl/COTRN01C.cbl` line 269): `READ … UPDATE` on TRANSACT with no REWRITE/UNLOCK; recorded as R only.
- **Dynamic XCTL targets** that come from `CDEMO-FROM-PROGRAM` (calling program in the COMMAREA) are resolved only by the menu/caller chains documented above.
- **MQ queue names** in COPAUA0C, COACCT01, CODATE01 come from the trigger message at runtime (`MQTM-QNAME`); reply/error queue names are not visible in source.
- `WS-USRSEC-FILE` (COADM01C, COMEN01C) and `WS-TRANSACT-FILE` (CORPT00C) are declared but never used in a file command.
